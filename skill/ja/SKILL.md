# water-divination — 測るのはモデルではなく、握っている側

『HUNTER×HUNTER』の水見式から6系統を借りている。コップを握ると水が変わり、その変わり方で系統が分かる。
ここでのコップは、あなた自身の1ヶ月ぶんの発話。

道具がやるのは**数えることと、尋ねるべきことを出すこと**まで。**判定するのはあなた**で、規律は下記。

## 手順

### 1. 計測

```
python tools/water_divination.py measure --since 2026-08-01 [--until 2026-08-31]
python tools/water_divination.py measure --last 30d
python tools/water_divination.py measure --on 2026-08-15
```

`out/divination.json`・暫定版の `out/water-divination.html`・質問1件につき1枠の `out/answers.json`
が出る。

**最初に読むのはスキャン報告**。source ごとの `read N, kept M` が、「空だった」と「そもそも無かった」を
区別する唯一の手がかり。本人の発話が50件を下回るなら**素材不足として判定しない**——窓を広げる。
薄いデータで自信ありげな判定を出すのが、この手の道具の一番の壊れ方。

### 2. 確認の対話 — 読みを出してから、最小限だけ

**先に読みを出す。** `measure` は「it looks like ◯◯」と名前を出してから確認事項を並べる。
質問を先に積むと興が冷める——水見式は宿題ではない。同型の質問は道具が既に1問へ畳んである
（`items` に対象が並ぶ）ので、**それ以上増やさない**。optional は訊かなくてよい。

道具は「正規表現では決まらなかったこと」を質問として出す。**1問ずつ、会話で、本人の言語で**尋ねる。

- **authorship（著者性）** — 貼り付けの可能性がある長さの引用。実物を見せて「これはあなたが書いたか」と訊く。
  「いいえ」ならその引用は**証拠から剥奪される**（道具が実際に効かせる）
- **probe（プローブ）** — 証拠が2件に満たない系統。その系統のプローブを投げ、**答えの形**を観察する
  （正しさではない）。何を見るかは各プローブに付いている
- **occasion（機会）** — シグナルや軸が0、または観測数が足りない項目。0は「能力が無い」と
  「機会が無かった」の両方を意味し、分けられるのは本人だけ。そもそも弱点なのかどうかが決まる
- **attribution（帰属）** — 軸が率を出した項目。その分子に入った仕事が他と同種だったかを訊く。
  簡単な仕事でしか成立しない数字は適性ではない
- **rare（稀少）** — 稀少事象が出た項目。その瞬間を見せて、意図してやったのかを訊く

答えは `out/answers.json` に `{"answer": "...", "note": "観察したこと"}` で記録する。
プローブは `answer` を `pass` / `fail` にし、note に「答えの形として何が見えたか」を書く。

最終的な読みに引用を載せる前に、必ず原本から文脈ごと引き直す:

```
python tools/nen_context.py "引用の一部"
```

exit 1 は**その引用がコーパスに存在しない**という意味。どれだけ良い引用でも、その時点で使えない。

#### 導線と想定問

誰がコップを握っても形は同じ。読みと名指しの間に立つのは**普通2問だけ**で、どちらも畳んである。
1回ずつ、対象を並べて訊く。

```
measure ──► 名前が出る ──► 2問 ──► verdict ──► カルテ1行
            （最大の分離）  帰属      両方埋まる   コーパスが消えても
                            著者性    まで拒否     残る唯一のもの
```

| 想定問 | それで確定すること | 「いいえ」の効果 |
|---|---|---|
| `attribution`（帰属） | その軸が数えた仕事が、他と同種だったか | 「簡単な方だった」→ 読みにそう書く。適性の主張としては降りる |
| `authorship`（著者性） | 読みを支える引用が本人の言葉か | 1件名指しすればその1件だけが証拠から落ち、系統ごと判定を失うこともある |
| `probe`（任意） | コーパスが示せなかった系統。プローブを投げ**答えの形**を見る | fail なら、その回は名指ししない |
| `occasion`（任意） | 0が「能力が無い」か「機会が無かった」か | 「機会が無かった」＝弱点ではない |
| `residual`（任意） | 残差に5系統が説明しないものがあるか | 「無い」が通常の答え |

**これ以上の質問を作らない。畳まれたものを開かない。** 「同種」「全部自分の言葉」と返ってきたら、
名前まであと1コマンド——訊き足さずにそこへ行く。

#### 人物描写（portrait）— 読み手が持ち帰る2〜3文

`answers.json` の `verdict.portrait` に書く。**必ず発話者の言語で**（コーパスが日本語なら日本語。
道具の文言も `patterns` の先頭ファイルでその言語になる）。

作り方（**定義文の貼り付けは禁止**）:
1. 名指しした系統の**実引用2〜3件**に共通する動きを1文で言う
2. その動きが何を可能にしているかを1文
3. その動きが何を犠牲にしているかを1文——**ここを書かないとお世辞になる**

**語り口は選べる。** このリポが想定しているのは、原作で水見式を施行する教師の口調——丁寧に順を追い、
誇張せず、分かっていないことは分かっていないと言い、代償があるなら先に言う。
占い師めいた断定と「あなたは特別です」型のお世辞は、どの語り口でも禁止。

### 3. 断定

answers ファイルの `verdict` ブロック（`main` / `roles` / `reads` / `summary`）を埋めてから:

```
python tools/water_divination.py verdict --result out/divination.json --answers out/answers.json
```

blocking な質問が未回答／系統が名指しされていない／名指しした系統が剥奪で証拠を失いプローブでも
補われていない、のいずれかなら**拒否される（exit 3）**。拒否は道具が正しく働いている状態。
名指しされたものに答えてから、もう一度走らせる。

## 判定の規律

0a. **名前は必ず出す。** コップが何も示さないことは無い。厳密さは**信頼度と根拠**に置くのであって、
   「答えが存在するか」に置かない。軸が示せばそれを根拠に、示さなければ**六つのかたち（プロフィール）
   の最大**を根拠に名指しし、`basis` を並べて書く（`axis` / `quotes`）。
   道具の `reading` がこれを返すので、それを覆すなら理由を書く。
   **`verdict.portrait` に、その人の言葉で1〜2文の人物描写を書く**——定義文の貼り付けではなく、
   実際の引用から立ち上げた文にする。ここが読み手の受け取る「自分の把握」になる。
0b. **レーダー（六つのかたち）は成績表ではない。** 発話のうちその系統の印を帯びた割合であって、
   効いたかどうかではない。低い系統を弱点と書かない——その期間その手を使わなかった、と書く。
   広い語彙を持つ系統は高く出るので、疑うなら `--audit-patterns` で特異度を測る。
0c. **水見式は「示したもの」を言う。測れなかったものを数え上げない。** コップは一つの反応を示す。
   示さなかった軸は**弱点でも宿題でもなく、この回の読みに入らないだけ**。数字は台帳とJSONに残るが、
   判定文と対話からは外す。「比較不能」と書き続けるのは測定レポートであって水見式ではない。
   道具側も同じ形で出す——反応した軸だけをカードに描き、残りは末尾に1行でまとめる。
   **逆向きに出た軸は別**: 「逆に出た」と名指しする（強みの列に混ぜない）。
1. **検証済み引用2件が無ければ名指ししない。** 系統を名指しできるのは (a) 言える形のシグナル値と
   (b) 原本で文脈まで読んだ引用2件が揃った時だけ。片方だけなら「未判定」であって、弱い肯定ではない。
2. **軸がある系統では、軸が語彙より上位。** 語彙が言うのは「その適性を使った」ことまでで、
   「効いた」と言えるのは軸だけ。シグナルは強いのに軸が弱い系統は**適性ではなく癖**——そう書く。
   観測数が足りず軸が出なかった系統は語彙に戻すが、**どちらに拠ったかを読みに明記する**。
3. **特質系には前提の門がある。** 残差が意味を持つのは、5系統が**実質発話の半分以上**を説明できている時だけ。
   下回る回は残差の大半が「検出器が取りこぼしたもの」であって「5系統が説明できないもの」ではないので、
   **道具が `usable: false` を返し、認定の材料にできない**（人の判断ではなく機械の門）。
   その回は特質系を認定しない——残差は読み物として見てよいが、根拠にしない。
   **特質系は残差を読んで、あなたが言う。** 道具がやるのは「5系統のどれでも説明がつかず、しかも
   AIが実際に動いた発話」を切り出すところまでで、**それが特別だとは一切言わない**（順位は
   「自分のコーパスの中で言い回しが珍しい順」＝読む順番であって評価ではない）。
   あなたの仕事はその残差を読み、次のどちらかを**理由つきで**述べること:
   - **「特質系の要素がある」＋それが何か＋なぜ他の5系統では説明できないのか**（1〜2行ずつ）
   - **「無い」**＋残差が何だったか（例: 単に短い依頼の集まりだった）
   引用は必ず本人に見せて確認する。**「無い」が通常の結果**であって、欠落ではない。
   件数やスコアから特質系を論じない——数える対象を決めた時点で、それは残差ではなくパターンになる。
3. **両義的なものを弱点に畳まない。** 証拠が両方を指すなら両方の読みを出し、どちらに寄るかだけ言う。
   中立や「そうするしかなかった手」を厳しく見せるために欠点へ書き換えた時点で、この判定は情報でなくなる。
   一番よくある壊れ方がこれ。
4. **主武器＝検証済み証拠が最も多い系統**であって、パーセントが最大の系統ではない。緩い正規表現の
   大きな数字は能力ではない。
5. **0は「不在」ではなく、理由つきの所見。** 本人の答えに従って「機会が無かった」「試みていない」と
   書くか、「語彙が捉えられていない可能性」と書く。**自分が選んだ引用に当たるまで語彙を広げるのは、
   計器を答えに合わせる行為**なのでやらない。
6. **回を追うごとに基準を上げない。** 系統が下がってよいのは、数値が下がった時か、実挙動の欠陥が
   出た時だけ。今回の読み手が前回より厳しい、は理由にならない。
7. **自分の癖を1行で申告する。** パターンを選んだ者が「何を証拠とみなすか」を決めている。この人の
   規約や文体を読んだ直後なら、その文書が語っていることを見つけやすくなる。**今回の判定のどこに
   それが乗りうるか**を具体的に書く。主武器が交代した回・ある系統を初めて認定した回・**同じセッションで
   計器を作ったり直したりした回**は、この会話を見ていないモデルにもう一度見せる。

## Hard gates

- 正規表現の件数だけで系統を名指ししない
- `nen_context.py` で引けない引用を載せない
- 拒否を回避するために answers を書き換えて断定しない（訊かれたことに答える）
- `patterns/*.json` の6系統の定義を凍結する。書き換えると過去の読みと将来の読みが比較不能になる。
  どうしても変えるなら版を上げ、読みの中でそう書く
- 読みから公開するものには本人の私的な発話が入る。手元から出す前に必ず確認を取り、
  資格情報・取引先名・第三者の言葉は載せない

## 繰り返し測るとき

**数値は必ず durable な場所へ落とす。** トランスクリプトは消える——次に測る頃には前回のコーパスが
残っていないことが普通で、その時は記録した数値だけが唯一の記録になる。
2つの読みが違う窓・違う計器の版・違うコーパスに基づくなら、そう明記する。
同じ6つの名前を使ったというだけでは、比較可能にはならない。
