# water-divination — v3（判定層が読む。計器は運ぶだけ）

成果物は**本人がもう一度読みたくなる読み物**である。AIを率いる側としての自画像に奥行きがあり、
本物の水見式の高揚があること。数字が全部正しくても、計測レポートになった時点で失敗とする。

## なぜ v3 が v1/v2 の判定エンジンを廃したか

v1・v2 は採点エンジンだった。パターンファイル、系統ごとのシグナル、計算で出す主武器。3日で9ラウンド
回したうち8ラウンドが「人を読む」のではなく「計器を直す」作業に費やされ、名指しされた系統は5通りに
振れた。振れた原因は毎回エンジンの改修であって、本人の側では何も起きていない。最後のラウンドは履歴を
生で読み、`pip install x` をプロジェクト最初の発話として、`cd project` を変化系として、自分自身の
ビルド実行を放出系の最上位実例として数えた。約4,500行の Python が生んだ読み物は、統計の文が5つだった。
記事自身の中心的な発見――**分析する側のAIの癖が判定に入り込む**――が、そのまま記録として残った形になる。

だから v3 は判定エンジンを持たない。スクリプトはテキストを運ぶだけ。判定層のモデル（強いもの）が
それを読んで系統を名指しする。そして判定層は流暢なまま間違えられるので、ページに載る引用は全て、
誰かの目に触れる前に生の履歴と機械照合される。

## 手順

### 0. つなぐ
過去ラウンドの記録があれば最後の1件を読む。前回の主武器と、残っている助言を確認する。
旧版の採点をもう一度走らせない。

### 1. テキストを運ぶ（スクリプト・機械的）
```
python tools/mizumi_corpus.py --out out
python tools/measure_setup.py --corpus out/corpus.jsonl
```
`out/` へ出るもの: `corpus.jsonl`（全発話を command / short / substantive / non_self に分類、
階層 founding / return / opening / sustained、transcript由来の `after` 付き）、`map.json`
（プロジェクト×月×文字数）、`chunk_A..C.txt`（substantive を時系列で三分割・コーダー書式）、
`heavy.txt`（120字以上の substantive）。`measure_setup.py` は公開採用率表に対する設定の深さに加えて、
テンポ・中断なしの自走の長さ・時間帯・訂正/質問/ルール/完成像/比喩の代理指標を出す。
Windows では `py -3 ファイル` で走らせる。複数行の `-c` は使わない。

### 2. 判定層が読む（委譲しない）
`out/heavy.txt` を**全部**、順番どおりに自分で読む。ここだけは要約で代替できない。
読み物が主張することは全て、自分が読んだ行か、あとで照合したコーダーの行までたどれること。

### 3. コーダーが候補を運ぶ（委譲・3〜4体並列）
時系列チャンク1つにつき1体（transcriptが濃い後半は2つに割る）。各体は `skill/ja/coder-rubric.md` を
読み、担当チャンクを**最後の行まで**読んでから `findings_X.json` を書く。系統ごとに最大12件、
strength 降順、原文どおりの引用・理由・その後に起きたこと。特質系候補・代償・言葉の癖・気づきも。
コーダーは抽出するだけで、系統を名指ししない。引用が原文どおりであることは契約であり、手順6で再照合される。

### 4. 系統を名指しする（判定層）
- **語彙ではなく、起きたこと**から名指しする。各系統の署名は出来事である（ルールが機構になった／
  比喩がファイルになった／制約が何週間も生き延びた／完成像が届いてAIが訊き返さずに作った／
  漠然とした願いが完成条件になった）。
- **検証済みの強い1件は、弱い10件に勝つ。** 件数は文脈であって、根拠そのものではない。
- 3つの状態を絶対に混ぜない: 立った（引用付きで名指し）／沈黙（探したが起きていない）／
  測れなかった（transcriptが無い＝ゼロではない）。
- 特質系は**加算的**。まず5系統を名指しし、その5つで説明できない残りを問う。名指しには反証の議論が
  要る（除外した系統ごとに1行）。見つからないのが通常の結果である。
- 代償にも強みと同じ厳密さを充てる。強みの代償は、その強みの裏側そのもの。
- 証拠から除外するもの: シェル／スラッシュコマンド、URLだけの行、他AIの返答の貼り付け、UI文字列、
  および秘密・金額・第三者の名前・家族の事情を含むもの。

### 5. 偏差値（方法を見せた上での励まし）
計算できる軸は1本だけ――**設定の深さ**を下の公開採用率表に当てる。
偏差値 = 50 + 10·Φ⁻¹(1 − p)。p は基準母集団のうち本人の水準以上にいる割合。
他の軸は全て判定層の見立てであり、ページ上では**見立てと明示する**（斜線のバー）。根拠を各1行添える。
見立てを計測値として出さない。

基準表（より新しい公開データが出たら更新し、ページに出典と日付を書く）。
出典: Build This Now, 公開 Claude Code リポジトリ2,500件, 2026-06。

| 機能 | 標本に占める割合 | それだけを持っている場合の偏差値 |

**5系統そのものには、公開されたユーザー単位の分布が存在しない。** その事実をページに書く。

### 6. 読み物を書く――口調はウイング
ページの順序。各節は飾りではなく荷重を持つ部材である:
1. **前口上** — 判定層自身の癖の申告。過去のラウンドが何を間違えたかを1段落で。
2. **地図** — 期間・発話数・セッション・稼働日・時間帯・月×プロジェクト・重心が動いた時期。
   本人が自分の記憶と照合できる半分。名指しはその後に来る。
3. **六つのコップ** — 系統ごとに: 反応（立った／沈黙／測れなかった）、署名、日付付きの原文引用2〜4件、
   （分かれば）その後に書かれたもの、その動きが可能にすること、その代償。主武器を先頭に、
   特質系は反証の議論を添えて最後に置く。
4. **偏差値** — 計算した軸と表、見立ての軸は斜線、根拠の行。
5. **代償** — 最大3つ。それぞれ名指しした強みの裏側であること。計測した代理指標を添える。
6. **言葉の癖** — 読者が憶えて帰るのはここ。
7. **明日から** — 修行は最大3つ、具体的で小さいもの。提案に留め、本人の設定を書き換えない。
8. **奥付** — 判定層・期間・コーパスの件数・コーダー数・出典・判定層の癖・除外したもの、
   そして引用照合の行。

口調の規律（『HUNTER×HUNTER』のウイング先生）――これは指示そのものなので日本語のまま置く:
丁寧語で順を追う（「いいですか」「よく聞いてください」）; 誇張しない; 分からないことは分からないと言う;
代償を褒め言葉より先に置く; 相手を子ども扱いしない; 禁止＝占い師めいた断定・能力バトル的な誇張・
「あなたは特別です」型のお世辞。定義文を判定として貼らない。引用を整えない。話者の言語で書く。

### 7. 誰かに見せる前に検証する
```
python tools/verify_quotes.py page.html
```
全ての `<blockquote><p>…</p>` が history.jsonl の行の部分文字列として原文どおりであること。
スクリプトは `scanned=N matched=M` を出力し、1件でも外れたら、**そして引用が0件でも** 1 で終了する。
この行を奥付へ書く。

### 8. 公開して記録する
- まず非公開で出す。共有する前に自分で読む。本人の言葉が載っているページである。
- 本人の台帳へ**1行だけ**追記する: 期間・コーパスの件数・系統ごとの判定と根拠引用のid・
  偏差値と根拠・コーダー構成・判定層の癖・除外したもの。過去の行は絶対に書き換えない。

## 越えてはいけない線

- **計測レポート禁止。** 分母と信頼区間が背骨になっているページは、正確さに関係なく失敗した読み物である。
- **機械照合された原文引用の無い名指し禁止。** `verify_quotes.py` が通ること。
- コマンド・貼付・他AIの文・秘密・金額・第三者・家族: 証拠にしない。ページにも載せない。
- 偏差値の見立ては見立てと明示する。計算したと呼べるのは設定の軸だけ。
- 特質系は加算的。名指しには反証の議論が要る。無いのが普通。
- 読み物は判定層が書く。コーダーは抽出のみ。
- 判定層は奥付で自分の癖を申告し、それがどこで読みに傾きを与えたかを書く。
- 過去の台帳の行は不変。
- **判定エンジンを復活させない。** 件数が欲しくなったら `measure_setup.py` へ代理指標を足し、
  代理指標として見せる。
