# agent-water-divination

[![test](https://github.com/kai-chop/agent-water-divination/actions/workflows/test.yml/badge.svg)](https://github.com/kai-chop/agent-water-divination/actions/workflows/test.yml)

AIエージェントを**率いている側の人間**にかける水見式である。AIの評価は世に溢れているが、対になる
もう半分――指示を書いている側――は誰にも測られていない。ここにあるのは、自分の Claude Code の履歴を
読める形のコーパスへ運ぶ道具で、それを判定層のモデルが読み、6系統のどれが実際に立っているかを
名指しする。強化系（目的を保つ）・放出系（頭の中の完成像を外へ出す）・変化系（感覚を判断基準へ
置き換える）・具現化系（理想を完成条件へ落とす）・操作系（出力ではなくルールを整える）・
特質系（5系統では説明できない組み合わせ）。6系統の出典はこのリポジトリが実装している記事
[AIに自分の水見式をさせてみた](https://note.com/aicreatekun/n/n3992b9080059)。読み物は水見式を
説明する側の人物であるウイング先生の口調で書かれるが、**ここにある道具はそれを書かない。**
テキストを運ぶだけである。

> 🇬🇧 **English**: [README.md](README.md)

## なぜ v3 が v1/v2 の判定エンジンを廃したか

v1・v2 はあなたを採点していた。パターンファイル、系統ごとのシグナル、計算で出す主武器。9ラウンド
回した結果それが測っていたのは自分自身の改修で、9回のうち8回は計器を直す作業に終わり、名指しされた
系統は5通りに振れた。振れた原因は毎回エンジンの改修であって、本人の側では何も起きていない。最後の版は
`pip install x` をプロジェクト最初の発話として数え、自分自身のビルド実行を放出系の最上位の証拠として
挙げた。記事自身の中心的な発見は**分析する側のAIの癖が判定に入り込む**ことで、エンジンはその実例に
なっていた。だから v3 はエンジンを丸ごと外した。判定層のモデルが生のテキストを読んで系統を名指しし、
判定層は流暢なまま間違えられるので、ページに載る引用は全て、誰かが読む前に生の履歴と機械照合される。

## 使い方

```
python tools/mizumi_corpus.py --out out
python tools/measure_setup.py --corpus out/corpus.jsonl
python tools/verify_quotes.py page.html
```

| | 何を書くか |
|---|---|
| `mizumi_corpus.py` | `out/corpus.jsonl`（全発話を分類）、`out/map.json`（プロジェクト×月×文字数）、`out/chunk_A..C.txt`（時系列の三分割・コーダー書式）、`out/heavy.txt`（120字以上＝判定層が自分で読む分） |
| `measure_setup.py` | 下の基準表に対する設定の深さ、テンポ、自走の長さ、時間帯、訂正／質問／ルール／完成像／比喩の代理指標 |
| `verify_quotes.py` | 引用ごとの `PASS`/`FAIL` と `scanned=N matched=M`。1件でも外れたら、**そして引用が0件でも** exit 1 |

既定値は `~/.claude/history.jsonl`・`~/.claude/projects`・`~/.claude/ledgers/prompt-authorship.jsonl`。
`--history` `--projects` `--sidecar` `--claude-dir` `--out` で上書きできる。Python 3.9 以上、依存ゼロ。
3本とも `--self-test` を持つ。

そのうえで **`skill/ja/SKILL.md` を自分のエージェントに渡す**（英語版は `skill/en/SKILL.md`）。
手順の実体はそちらにある――判定層が何を読むか、系統をどう名指しするか、何を絶対に証拠にしないか、
ページをどういう順序で書くか。

## 何を除外するか、なぜか

読み物が読み返す価値を持つのは、そこにある言葉が本人のものである時だけである。コーパスを書く前に
4つが落とされる。どれも本人について何かを示す材料ではない。

- **コマンド。** `pip install`・`cd`・`git`・スラッシュコマンド。打ったのは本人だが、機械を操作して
  いるのであって、率いてはいない。
- **貼り付け。** `history.jsonl` は打った文と貼った内容を別のフィールドで持つので、貼付本文は
  そもそもテキストに入らない。
- **他AIの文。** 難しいのはここで、他モデルの裁定文が自分のプロンプト欄へ直接貼り込まれている場合が
  ある。`classify_authorship()` は3つの形を名指しする。`attributed`（他AIを指すラベルの後に長い本文が
  続く）、`relay`（貼付プレースホルダを本人の枠が囲んでいる＝本人の言葉なので残す）、`suspect_ai`
  （ラベルは無いが本文が裁定文・報告文に読める＝裁定の書き出し、見出し、脚注参照、3点以上の箇条書き、
  AIの一人称）。1つ目と3つ目は全ての集計から落とす。任意で `UserPromptSubmit` フックが捕捉時に
  サイドカーを書ける――1発話1行の
  `{"ts_ms","session","verdict","reasons","chars","secret"}` ――これは事後の推定を上書きする。
  捕捉時点では推定ではなく答えが分かっているからである。
- **秘密。** トークンや鍵は照合され、コーパス上では `[SECRET REDACTED]` に置き換わる。
  伏せた件数は出力される。

## 偏差値

基準となる母集団が実在する軸は1本だけなので、計算するのも1本だけである。
偏差値 = 50 + 10·Φ⁻¹(1 − p)。p は母集団のうち本人の水準以上にいる割合。

| 機能 | 標本に占める割合 | それだけを持っている場合の偏差値 |
|---|---|---|
| CLAUDE.md | 84.9 % | 40 |
| settings.json | 41.0 % | 52 |
| skills | 28.1 % | 56 |
| カスタムコマンド | 25.6 % | 57 |
| カスタムサブエージェント | 24.6 % | 57 |
| MCP | 17.0 % | 60 |
| hooks | 13.3 % | 61 |

出典: Build This Now, 公開 Claude Code リポジトリ2,500件, 2026-06。

**5系統そのものには、公開されたユーザー単位の分布が存在しない。** そこに付く数字は全て判定層の
見立てであり、ページ上で見立てと明示しなければならず、このリポジトリの何かが算出したものではない。

## プライバシー

全てローカルで動く。何もアップロードしないし、この3本のスクリプトにはネットワーク呼び出しが1つも無い。
コーパスは本人の言葉そのものなので、そのように扱うこと――`out/` は gitignore 済みで、ページは誰かに
見せる前に自分で読むこと。読み物を公開する前に `tools/verify_quotes.py` を通す。本人を引用するページは
本人を正確に引用しなければならないし、引用が1件も無いページはこの検査を通過ではなく失敗として扱う。
